## 開発ツールと手法
* 依存パッケージは `requirements.txt` で管理し、`python3 -m venv .venv` で作成した仮想環境にインストールする
* 開発は本リポジトリの `CLAUDE.md` に定義されたドキュメント駆動プロセス(`docs/` → `.steering/` → 実装)に従う
* 自動テスト・CIは現時点では未整備(個人利用の小規模プロジェクトのため)。将来的にシグナル判定ロジック(`stock_signals.py`)の単体テストを追加する余地がある
* コーディング規約の詳細は `docs/development-guidelines.md` に別途定義する

## 技術的制約と要件
* **yfinanceの非公式性**: yfinanceはYahoo Financeの非公式スクレイピング/APIラッパーであり、Yahoo側の仕様変更やアクセス制限により動作しなくなる可能性がある。致命的エラー時は画面にエラーメッセージを表示し、アプリ全体は停止させない。
* **ネットワーク環境依存**: 実行環境によっては(社内プロキシ・サンドボックス環境等)Yahoo Finance関連ドメインへの通信がブロックされる場合がある。その場合はローカルPC等、制限のないネットワークで実行する必要がある。
* **永続化なし**: 現時点でデータベースやファイルへの保存は行わない。ウォッチリスト(登録した証券コード)はセッション中のみ保持され、ブラウザを閉じると消える。将来的にウォッチリストを保存したい場合は `st.session_state` の活用、またはローカルファイル(JSON等)への保存を検討する。
* **東証銘柄限定**: 現時点では証券コードに `.T` サフィックスを付与する前提であり、米国株など他市場には対応していない。

## パフォーマンス要件
* 個人(単独ユーザー)利用を前提とし、同時アクセスや高負荷は想定しない
* 最大10銘柄をまとめて表示する際、1銘柄あたりのデータ取得は逐次実行してよい(並列化は必須要件としない)。実用上、10銘柄の一覧表示が数秒〜十数秒程度で完了することを目安とする
* Streamlitの標準キャッシュ機構(`st.cache_data`)を用いて、同一銘柄・同一期間への再アクセス時の取得待ち時間を削減することを推奨する(実装は `.steering/` の作業単位で対応)
