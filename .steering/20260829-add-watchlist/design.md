# 設計: ウォッチリスト機能の追加

## 実装アプローチ
1. サイドバーの証券コード入力を単一テキスト欄からテキストエリア(改行またはカンマ区切りで複数入力可)に変更する
2. 入力テキストを解析して証券コードのリストに変換する関数 `parse_watchlist_codes` を `stock_signals.py` に追加する(トリム・重複除去・最大10件の上限チェックを行う)
3. `app.py` 側で、解析済みの各証券コードに対して既存の `fetch_price_history` → `compute_indicators` → `evaluate_sell_signal` をループ実行する
   * 取得に成功した銘柄はサマリー(証券コード・最新終値・シグナルレベル・主な理由)としてリストに集計する
   * 取得に失敗した銘柄はエラーメッセージとともに別リストに集計し、他銘柄の処理は継続する(1銘柄の失敗で全体を止めない)
4. シグナルレベルの強さ順(強 > 中 > 弱 > なし > 判定不可)にソートするため、レベル文字列を並び順の数値に変換する対応表を `stock_signals.py` に定数として追加する
5. 一覧テーブル(`st.dataframe`)の下に `st.selectbox` を配置し、詳細表示する銘柄を選択できるようにする。初期選択値は一覧の先頭(=最もシグナルが強い銘柄)とする
6. 選択された銘柄について、既存のチャート描画ロジック(ローソク足・移動平均・売買代金・データテーブル)をそのまま流用して表示する
7. `fetch_price_history` の呼び出しを `st.cache_data` でラップした関数を `app.py` 側に追加し、同一銘柄・同一期間への再取得を減らす(`stock_signals.py` 自体はUIフレームワーク非依存のまま保つ)

## 変更するコンポーネント
* **`stock_signals.py`**
  * 追加: `parse_watchlist_codes(raw_text: str, max_codes: int = 10) -> list[str]`
  * 追加: シグナルレベルのソート優先度を表す定数(例: `SIGNAL_LEVEL_ORDER`)
  * 既存関数(`to_ticker_symbol` / `fetch_price_history` / `compute_indicators` / `evaluate_sell_signal`)は変更しない
* **`app.py`**
  * サイドバー: テキストエリアによる複数コード入力に変更
  * 追加: 銘柄ごとのループ処理、一覧サマリーの構築、エラー銘柄の表示
  * 追加: 一覧テーブル表示、銘柄選択用の `st.selectbox`
  * 変更: 既存の詳細チャート描画を「選択中の1銘柄」に対して実行するように変更(処理自体はほぼ流用)
  * 追加: `st.cache_data` でラップしたデータ取得ヘルパー

## データ構造の変更
* 一覧サマリーは `list[dict]`(または簡易な `pandas.DataFrame`)として保持する。各要素は以下を持つ:
  * `code`: 証券コード
  * `symbol`: yfinance用シンボル
  * `latest_close`: 最新終値
  * `level`: シグナルレベル
  * `primary_reason`: 判定理由の先頭1件(一覧表示用の要約)
* 銘柄ごとの詳細データ(indicators付きDataFrame、`SellSignal`)は、選択中の銘柄のみメモリに保持すればよく、全銘柄分を常に保持する必要はない(必要になった時点で再取得、`st.cache_data` で高速化)

## 影響範囲の分析
* `stock_signals.py` の既存関数のシグネチャ・挙動は変更しないため、単体のロジックへの影響はない(追加のみ)
* `app.py` のUI構成は大きく変わるため、単一銘柄時代のUIフローはウォッチリスト一覧+詳細選択のフローに置き換わる
* `README.md` の「起動方法」セクションは、複数コード入力の説明に更新が必要
* `docs/` 側は本作業着手前に既に更新済み(`product-requirements.md` / `functional-design.md`)であり、追加の永続的ドキュメント更新は不要
