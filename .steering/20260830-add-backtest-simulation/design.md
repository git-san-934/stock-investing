# 設計: 過去データでのシミュレーション機能の追加

## 実装アプローチ
1. `stock_signals.py` に、全期間の日ごとのシグナルレベルをベクトル演算で算出する `compute_signal_levels(df) -> pd.Series` を追加する。`evaluate_sell_signal` と同じ閾値条件(売買代金急増・高値圏・デッドクロス)を用いるが、1日分ではなく全行に対して算出する点が異なる。
   * 既存の `evaluate_sell_signal` は「最新日の判定理由の文章」を作るための関数として維持し、変更しない
   * 閾値ロジックが2箇所に存在することになるため、両関数の冒頭に「条件を変更する際は両方を揃えること」を示す短いコメントを付ける
2. `stock_signals.py` に、シミュレーションを行う `simulate_sell_strategy(df, sell_levels=("強", "中")) -> list[Trade]` を追加する
   * ルール: 期間最初の営業日の終値で買う → シグナルレベルが `sell_levels` に該当した日の終値で売る → シグナルが「なし」に戻った次の営業日の終値で買い直す → 期間最終日まで保有していた場合は含み損益として計上する
   * 売買記録は `Trade` データクラス(購入日・購入価格・売却日・売却価格・損益率・保有中フラグ)のリストとして返す
3. `stock_signals.py` に、買い持ち(ずっと保有した場合)の損益率を返す `buy_and_hold_return(df) -> float` を追加する
4. `app.py` の各銘柄のexpander内に、シミュレーション結果セクションを追加する
   * `simulate_sell_strategy` の結果から、複利計算で「シグナル通り売買した場合の合計損益率」を算出する(各取引の損益率を掛け合わせる)
   * `st.metric` で「シグナル通り売買」と「買い持ち」の損益率を並べて表示する
   * 個別取引を一覧テーブル(`st.dataframe`)で表示する。保有中の行は「状態: 含み損益」、確定した行は「状態: 確定」と表示する
   * シミュレーションのルールと「参考情報であり将来を保証しない」旨の注記を `st.caption` で表示する

## 変更するコンポーネント
* **`stock_signals.py`**
  * 追加: `compute_signal_levels(df) -> pd.Series`
  * 追加: `Trade` データクラス
  * 追加: `simulate_sell_strategy(df, sell_levels) -> list[Trade]`
  * 追加: `buy_and_hold_return(df) -> float`
  * 既存関数は変更しない
* **`app.py`**
  * 各銘柄のexpander内に、シミュレーション結果の表示ブロックを追加する

## データ構造の変更
* `Trade` データクラス: `entry_date`(購入日) / `entry_price`(購入価格) / `exit_date`(売却日、保有中の場合は最終営業日) / `exit_price`(売却価格、保有中の場合は最新終値) / `return_pct`(損益率) / `is_open`(保有中かどうかのフラグ)

## 影響範囲の分析
* 既存のシグナル判定(`evaluate_sell_signal`)・ウォッチリスト一覧表示のロジックには影響しない(追加のみ)
* `app.py` の各銘柄expander内の表示量が増える(チャート・データテーブルに加えてシミュレーション結果が追加される)ため、画面が縦に長くなる。ページの構成自体は変更しない
* 表示期間(6ヶ月/1年/2年)によってシミュレーション対象期間が変わるため、期間が短いとシグナル発生回数が少なくなり、参考にしづらい場合がある(その旨を注記で補足する)
