# 設計: 買い時/様子見の帯表示 と AIによる有望10銘柄選定機能の追加

## 機能1: 買い時/様子見の帯表示

### 実装アプローチ
1. `stock_signals.py` に、全期間の日ごとの状態を算出する `compute_buy_zone_levels(df) -> pd.Series` を追加する。
   * 終値が25日移動平均線(`ma_short`)より上 → `"買い時"`
   * 終値が25日移動平均線より下 → `"様子見"`
   * `ma_short` がNaN(データ不足)の日 → `pd.NA`(着色しない)
   * 既存の `evaluate_sell_signal`(前日比のクロス検知)とは独立した関数とし、既存ロジックには一切手を入れない。
2. `app.py` の株価チャート描画部分で、`compute_buy_zone_levels` の結果から連続する同一状態の区間(開始日・終了日)を求め、`plotly.graph_objects.Figure.add_vrect` でチャート背景に帯を描画する。
   * 色は利用者の希望(TradingViewのボラティリティ帯表示を参考)に合わせ、以下を採用する。
     * 買い時(25日線より上): `rgba(220, 53, 69, 0.18)`(赤)
     * 様子見(25日線より下): `rgba(255, 193, 7, 0.18)`(黄色)
   * 透明度を持たせ`layer="below"`で背面に描画することで、ローソク足の陽線/陰線の色とは重ならないようにする(2026-08-31: 当初は緑/グレー案だったが、利用者の希望する配色イメージに合わせて赤/黄色に変更)。
   * `layer="below"` を指定し、ローソク足・移動平均線より背面に描画する。
   * vrectそのものは凡例に出ないため、凡例表示用に幅0のダミー`go.Scatter`(該当色の四角マーカー)を2本追加し、「買い時」「様子見」の凡例項目として表示する。
3. 区間の切り出しは、状態が変化した行を境界として `groupby` (状態値の変化点で連番を振る一般的なpandasイディオム: `state.ne(state.shift()).cumsum()`)でまとめ、各グループの最初と最後の日付を区間の開始・終了とする。

### 変更するコンポーネント
* **`stock_signals.py`**
  * 追加: `compute_buy_zone_levels(df) -> pd.Series`(値は `"買い時"` / `"様子見"` / `pd.NA`)
  * 既存関数は変更しない
* **`app.py`**
  * 銘柄詳細の株価チャート(`price_fig`)構築部分に、背景帯の描画処理と凡例用ダミートレースを追加する
  * 帯の意味を説明する `st.caption` を追加する

### データ構造の変更
* 新しいデータクラスは追加しない。区間は `(start_date, end_date, state)` のタプルのリストとして関数内でのみ扱う一時データとする。

### 影響範囲の分析
* 既存の売り検討シグナル判定・ウォッチリスト一覧・シミュレーション機能には影響しない(チャート描画部分への追加のみ)
* 表示期間が長い(2年・10年)場合、状態の切り替わり回数が増え `add_vrect` の呼び出し数が増えるが、Plotlyの描画性能上は許容範囲(数百区間程度までは問題ない想定)

## 機能2: AIによる有望10銘柄選定

### 実装アプローチ
1. **対象ユニバースの静的データ**: `data/tse_universe.csv`(新規ディレクトリ)を追加し、証券コード・銘柄名・市場区分を保持する。実装時にJPXが公表する上場銘柄一覧を元に作成する。全銘柄の取得・整備が困難な場合は、東証プライム市場の主要銘柄を中心とした静的リストを代替として用い、その旨をREADME・画面上に明記する(完全性を保証しない前提を明示)。
2. `stock_signals.py` に以下を追加する。
   * `load_universe() -> pd.DataFrame`: `data/tse_universe.csv` を読み込む
   * `fetch_price_history_batch(codes: list[str], period: str) -> dict[str, pd.DataFrame]`: `yfinance.download` のマルチティッカー機能を使い、複数銘柄をまとめて取得する(1銘柄ずつ呼び出すより通信回数を大幅に削減する)。取得に失敗した銘柄はスキップする。
   * `score_stock(df: pd.DataFrame) -> float | None`: 指標を組み合わせたスコアを算出する。データ不足等でスコア算出不可の場合は `None` を返す。スコア構成(重み付けは実装時に調整可):
     * 25日移動平均線からの上方乖離率(`(Close - ma_short) / ma_short`)
     * ゴールデンクロス状態(`ma_short > ma_long` なら加点)
     * 直近の売買代金の増加度合い(`turnover_ratio`)
     * 直近5営業日騰落率
   * `select_top_promising(n: int = 10) -> list[dict]`: ユニバース全銘柄に対し `fetch_price_history_batch` → `compute_indicators` → `score_stock` を適用し、スコア上位n件を、算出根拠(各指標値)付きで返す
3. `app.py` に新しいタブ(`st.tabs` で「ウォッチリスト」「有望銘柄(AI選定)」の2タブ構成にする)を追加し、以下を表示する。
   * 実行ボタン(自動実行はしない。処理コストが高いため明示的なトリガーとする)
   * 実行中は `st.progress` で進捗を表示する
   * 結果はスコア上位10銘柄を、コード・銘柄名・スコア・算出根拠の指標値を含むテーブルで表示する
   * 「投資助言ではない参考情報である」旨と、「対象ユニバースは完全な東証全銘柄ではない場合がある」旨を明記する
4. **キャッシュ**: `select_top_promising` の結果を `@st.cache_data(ttl=86400)`(24時間)でキャッシュし、同一日内の再実行では再計算しない。

### 変更するコンポーネント
* **新規ファイル**: `data/tse_universe.csv`
* **`stock_signals.py`**
  * 追加: `load_universe`, `fetch_price_history_batch`, `score_stock`, `select_top_promising`
  * 既存関数(`fetch_price_history` 等)は変更せず、単一銘柄取得用として引き続き利用する
* **`app.py`**
  * `st.tabs` によるタブ構成への変更(既存のウォッチリスト表示は1つ目のタブに移動するのみで、内容・ロジックは変更しない)
  * 2つ目のタブとして「有望銘柄(AI選定)」セクションを追加

### データ構造の変更

### 影響範囲の分析
* 既存のウォッチリスト機能・シグナル判定・シミュレーション・機能1(帯表示)には影響しない(独立したタブ・独立した関数として追加)
* `app.py` の画面構成が「ウォッチリスト」「有望銘柄」の2タブに変わるため、既存利用時の導線が変わる(サイドバーの証券コード入力は引き続き「ウォッチリスト」タブに対応)
* 全銘柄スキャンは処理時間・yfinanceへのリクエスト数の観点で最も重い処理になるため、実行ボタン方式・キャッシュ・バッチ取得で負荷を抑える
* `docs/repository-structure.md` のファイル配置ルールに、新規 `data/` ディレクトリの用途(静的な銘柄ユニバースデータ)を追記する必要がある
